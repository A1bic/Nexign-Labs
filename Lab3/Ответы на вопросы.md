## Этап 1

```text
[A1@A1-pc Lab3]$ gcc -c vector_math.c -o vector_math.o
[A1@A1-pc Lab3]$ g++ -c main.cpp -o main.o
[A1@A1-pc Lab3]$ ar rcs libmath_static.a vector_math.o
[A1@A1-pc Lab3]$ g++ main.o -L. -lmath_static -o app_static
[A1@A1-pc Lab3]$ ./app_static
Library version: v2.4.1-release
Dot product result: 32
```

1. r - добавляет файлы в архив, а если файл с таким именем уже есть, заменяет его. c - создаёт архив, если его нет, без лишнего сообщения. s - создаёт индекс символов архива (как ranlib), чтобы линковщик быстро находил, в каком .o лежит нужный символ.

Если запустить команду второй раз, то архив не пересоздаётся и файлы не дублируются, vector_math.o просто заменяется новым, а индекс обновляется
```text
[A1@A1-pc Lab3]$ ar rcsv libmath_static.a vector_math.o
r - vector_math.o
[A1@A1-pc Lab3]$ ar t libmath_static.a
vector_math.o
```

2.
```text
[A1@A1-pc Lab3]$ nm main.o
                 U _GLOBAL_OFFSET_TABLE_
                 U _ZNSolsEPFRSoS_E
                 U _ZNSolsEi
                 U _ZSt21ios_base_library_initv
                 U _ZSt4cout
                 U _ZSt4endlIcSt11char_traitsIcEERSt13basic_ostreamIT_T0_ES6_
                 U _ZStlsISt11char_traitsIcEERSt13basic_ostreamIcT_ES5_PKc
                 U __stack_chk_fail
                 U dot_product
                 U get_lib_version
0000000000000000 T main
```
main не искажается, потому что это точка входа, её вызывает стартовый код рантайма на C (__libc_start_main), который ищет именно символ main. Плюс main нельзя перегрузить, так что кодировать типы аргументов в имени не нужно, и компилятор всегда делает её с C-линковкой. dot_product и get_lib_version не искажены из-за extern "C" в заголовке.

## Этап 3

```text
[A1@A1-pc Lab3]$ g++ -L. -lmath_dynamic main.o -o app_wrong_order
[A1@A1-pc Lab3]$ echo $?
0
[A1@A1-pc Lab3]$ g++ main.o -L. -lmath_dynamic -o app_correct
[A1@A1-pc Lab3]$ LD_LIBRARY_PATH=. ./app_correct
Library version: v2.4.1-release
Dot product result: 32
```

С .so на Arch шаг 1 не падает, т.к. тут gcc по умолчанию не передаёт линковщику --as-needed (в Ubuntu передаёт). С этим флагом или со статической библиотекой ошибка появляется
```text
[A1@A1-pc Lab3]$ g++ -Wl,--as-needed -L. -lmath_dynamic main.o -o app_wrong_order
/usr/bin/ld: main.o: in function `main':
main.cpp:(.text+0x5f): undefined reference to `get_lib_version'
/usr/bin/ld: main.cpp:(.text+0xb0): undefined reference to `dot_product'
collect2: error: ld returned 1 exit status
[A1@A1-pc Lab3]$ g++ -L. -lmath_static main.o -o app_wrong_order
/usr/bin/ld: main.o: in function `main':
main.cpp:(.text+0x5f): undefined reference to `get_lib_version'
/usr/bin/ld: main.cpp:(.text+0xb0): undefined reference to `dot_product'
collect2: error: ld returned 1 exit status
```

1. Линковщик идёт по аргументам один раз слева направо. Объектные файлы он добавляет в E всегда, их определения кладёт в D, а неразрешённые ссылки в U. Из библиотеки он берёт только то, что закрывает символы, которые в данный момент лежат в U, остальное выбрасывает и к библиотеке больше не возвращается. Если в конце U не пустое - undefined reference.

При порядке -lmath_dynamic main.o библиотека обрабатывается первой, когда U ещё пустое, поэтому из неё ничего не берётся. Потом main.o добавляет в U get_lib_version и dot_product, но библиотека уже пройдена, и в конце они так и остаются в U. При правильном порядке main.o сначала кладёт их в U, а потом библиотека их разрешает.


## Этап 4

После того как блок extern "C" в vector_math.h был закомментирован (копия vector_math_no_extern_c.h и main_no_extern_c.cpp)
```text
[A1@A1-pc Lab3]$ g++ -c main_no_extern_c.cpp -o main_no_extern_c.o
[A1@A1-pc Lab3]$ g++ main_no_extern_c.o -L. -lmath_dynamic -o app_no_extern_c
/usr/bin/ld: main_no_extern_c.o: in function `main':
main_no_extern_c.cpp:(.text+0x5f): undefined reference to `get_lib_version()'
/usr/bin/ld: main_no_extern_c.cpp:(.text+0xb0): undefined reference to `dot_product(int const*, int const*, int)'
collect2: error: ld returned 1 exit status
```

1.
```text
[A1@A1-pc Lab3]$ nm main_no_extern_c.o | grep -E 'dot|get_lib'
                 U _Z11dot_productPKiS0_i
                 U _Z15get_lib_versionv
[A1@A1-pc Lab3]$ nm libmath_dynamic.so | grep -E 'dot|get_lib'
00000000000010f6 T dot_product
00000000000010e9 T get_lib_version
```
Теперь в C++ имена искажены: _Z11dot_productPKiS0_i (11 - длина имени, PKi - const int*, S0_ - повтор того же типа, i - int) и _Z15get_lib_versionv (v - нет аргументов). А библиотека собрана компилятором C и экспортирует просто dot_product и get_lib_version. Для линковщика это разные имена, поэтому он их не находит. extern "C" как раз говорит компилятору C++ не искажать имена этих функций.
