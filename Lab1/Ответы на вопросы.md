4. файл, скомпилированный с флагом -O0 несколько меньше чем тот, что был скомпилирован с флагом -O2. Первый файл в 1.4 раза больше чем второй, т.к. эти флаги отвечают за оптимизации и размер файла. Чем больше число, тем больше оптимизаций, выше скорость работы программы и тем меньше размер файла

5. Для умножения используется операция mul w0, w8, w9 (w0 = w8 * w9). При этом данные читаются из памяти дважды (w8 и w9 это одно и то же число в разных регистрах)

```text
__Z6squarei:                            ; @_Z6squarei
	.cfi_startproc
; %bb.0:
	sub	sp, sp, #16
	.cfi_def_cfa_offset 16
	str	w0, [sp, #12]
	ldr	w8, [sp, #12]
	ldr	w9, [sp, #12]
	mul	w0, w8, w9                       ; -- Вот эта строка
	add	sp, sp, #16
	ret
	.cfi_endproc
                                        ; -- End function
	.globl	__Z14sum_of_squaresii           ; -- Begin function _Z14sum_of_squaresii
	.p2align	2
```

6. Для передачи аргументов в вызов sum_of_squares используются регистры w0 и w1. Сама функция main записывает значения переменных (3 и 4) в эти регистры, а функция sum_of_squares считывает оттуда же значений и записывает результат в w0, а main впоследствие читает из w0 результат. Без соглашения о вызовах одна функция не могла бы ничего узнать о том, в какой регистр была положена переменная другой функцией

7. Во втором файле (-O2) функция square не исчезла. В ней стало меньше инструкций, но она не исчезла полностью. Однако она пропала из функции main. Так как сама функция не делает ничего умнее арифметики, компилятор просто во время компиляции выполнил эти инструкции и сразу подставил ответ вместо самой функции (25)

8. Переменной MAGIC вообще нет на выводе. 
```text
000000000000005c T __Z12dump_counterv
000000000000001c T __Z14sum_of_squaresii
0000000000000000 T __Z6squarei
0000000000000180 S _global_counter
0000000000000070 T _main
                 U _printf
00000000000000dc s l_.str
0000000000000000 t ltmp0
0000000000000180 s ltmp1
00000000000000dc s ltmp2
0000000000000100 s ltmp3
```
Это происходит из-за того, что эта переменная на самом деле константа, то есть она не изменяется во время выполнения программы и компилятору проще просто подставить это самое значение чем выделять под нее память и т.д.
А если бы MAGIC и существовала в качестве переменной (const int), то она бы имела тип R потому что она неизменяемая (как и писалось выше)

9. команда size показывает, сколько байт занимает каждый сегмент, если объектный файл слинковать в исполняемый
```text
__TEXT  __DATA  __OBJC  others  dec     hex
256     4       0       128     388     184
```
__TEXT - это исполняемые инструкции + строковые литералы
__DATA - это только global_counter, т.к. это единственная переменная с изменяемым значением
__OBJC = 0, т.к. у нас нет ни одного созданного объекта 
others - остальные данные (скорее всего метаданные Mach-O)
